# Agent 评审清单

用于代码审查、交付前自查和回归分析。评审以可导致数据丢失、隐私泄漏、文件破坏或协议不兼容的问题为优先，不以个人风格偏好淹没真正风险。

## 1. 优先级

### P0：必须立即阻止

- 可删除、覆盖或错误移动用户真实文件；
- 明文保存或日志泄漏 API Key；
- 默认上传用户内容且没有明确操作；
- 数据库恢复/迁移可无提示破坏主要数据；
- 发布资产与标签源码不一致；
- 外部模块路径校验可执行模块目录外程序。

### P1：合并前修复

- 批量写入非事务导致部分成功；
- 删除记录绕过文件历史；
- 改名数据库失败后文件状态未处理或误报；
- 旧数据库/备份无法升级；
- 新 Tauri 命令未注册或前后端字段不一致；
- AI 未经审核直接写入；
- 模块禁用后仍可调用；
- 公共协议不兼容但没有版本策略。

### P2：应尽快修复

- 重要错误路径没有测试；
- 浏览器预览与桌面接口明显漂移；
- 文档描述与实现不一致；
- 可访问性、空态、加载态或失败态缺失；
- 性能会随 Snapshot/历史增长明显恶化但没有限制。

### P3：改进建议

- 命名、局部结构、重复代码；
- 不影响正确性的样式一致性；
- 可选的测试可读性或文档补充。

## 2. 通用正确性

- [ ] 需求中的所有用户路径都被覆盖，而不只是 happy path。
- [ ] 输入在 Rust 信任边界再次校验。
- [ ] 新记录与更新记录的 ID 语义一致。
- [ ] 空值使用 `null` / 空字符串的约定未混淆。
- [ ] 日期格式和本地时间语义一致。
- [ ] 错误不会被吞掉或误报成功。
- [ ] 写入后 UI 从事实来源刷新，而不是保留陈旧局部状态。
- [ ] 不相关功能没有被顺手改写。

## 3. 数据库

- [ ] foreign key、cascade 和索引符合关系。
- [ ] 多表操作有事务。
- [ ] 失败时不会留下半成品。
- [ ] schema 变化更新 `user_version` 或有明确兼容策略。
- [ ] 新库、旧库和恢复路径都能获得所需表/列。
- [ ] 备份执行完整性检查，恢复版本范围明确。
- [ ] 模块私有数据没有污染核心 Snapshot。
- [ ] 删除后的无引用清理不会删掉历史仍需引用的数据。

## 4. 文件系统

- [ ] 路径已规范化。
- [ ] 文件/目录类型已验证。
- [ ] 课程相对路径不能逃逸根目录。
- [ ] 同路径大小写和重复项处理符合 Windows 行为。
- [ ] 改名前预览并检查目标冲突。
- [ ] 不静默覆盖文件。
- [ ] 文件操作与数据库之间有补偿或明确恢复说明。
- [ ] 撤回验证最新记录、当前路径、目标占用、大小和 mtime。
- [ ] 删除业务记录不删除真实学习文件。
- [ ] 测试只操作临时文件。

## 5. 前端与服务层

- [ ] 页面不直接调用 Tauri `invoke`。
- [ ] `src/types.ts` 与 Rust serde 结构一致。
- [ ] `src/service.ts` 同时有桌面和预览路径。
- [ ] 新命令已在 `src-tauri/src/lib.rs` 注册。
- [ ] 模态框有关闭、错误、加载和重复提交防护。
- [ ] 破坏性操作有明确确认。
- [ ] 表单保留用户输入，不因失败意外清空。
- [ ] 按钮、输入和导航具有可理解标签。
- [ ] 最小窗口尺寸下主要操作仍可达。

## 6. AI、网络与凭据

- [ ] 用户明确触发后才发送请求。
- [ ] UI 清楚说明发送的文字和附件。
- [ ] API Key 只在后端/凭据管理器中处理。
- [ ] 错误和日志不包含认证头、Key 或完整敏感响应。
- [ ] URL 强制 HTTPS，只有明确 loopback 例外。
- [ ] 文件类型、MIME、大小和模型能力在发送前校验。
- [ ] HTTP 超时合理，临时上传尽力清理。
- [ ] 模型输出作为不可信 JSON 校验。
- [ ] 非法 DDL 和未知课程不会被臆测填充。
- [ ] 保存前有人工审核。
- [ ] 模拟测试不依赖真实服务商账号。

## 7. 模块系统

- [ ] 清单 ID、能力、名称和 executable 校验完整。
- [ ] 外部模块不能冒用 `builtin.*`。
- [ ] executable 规范化后仍在模块目录内。
- [ ] 禁用状态在宿主端强制执行。
- [ ] 能力必须已声明。
- [ ] 不使用 shell 启动外部模块。
- [ ] 输入、stdout 和超时上限仍生效。
- [ ] stderr 不混入成功 stdout。
- [ ] 协议版本和 `result` 字段已验证。
- [ ] 文档没有把外部模块描述成沙箱。
- [ ] 公共能力变化有兼容策略和 `MODULES.md` 更新。

## 8. 隐私与安全

- [ ] 没有新增隐式遥测、同步或上传。
- [ ] 数据位置和备份范围准确。
- [ ] 用户路径和真实课程内容没有进入 fixture、截图或日志。
- [ ] 不执行未信任文件中的指令。
- [ ] opener 只用于明确 URL/文件。
- [ ] CSP 影响已评估。
- [ ] 外部模块权限边界对用户可见。

## 9. 测试与验证

- [ ] `git diff --check` 通过。
- [ ] `pnpm lint` 退出码为 0，新增 warning 已说明。
- [ ] `pnpm build` 通过。
- [ ] 相关 Rust 测试通过。
- [ ] 全部 Rust lib tests 通过。
- [ ] 高风险路径有失败测试。
- [ ] 桌面专属功能未只用浏览器预览验证。
- [ ] 影响打包时执行了 `pnpm desktop:build`。
- [ ] 文档本地链接可解析。

## 10. 发布

- [ ] `package.json`、Tauri、Cargo、Cargo.lock 和内置模块版本一致。
- [ ] CHANGELOG 和 README 示例已更新。
- [ ] 标签符合 `vMAJOR.MINOR.PATCH`。
- [ ] 标签指向预期提交。
- [ ] 没有移动公开标签。
- [ ] GitHub workflow 通过 lint、测试和桌面构建。
- [ ] installer、portable 和 SHA256SUMS 三项资产齐全。
- [ ] Release 不是意外 draft/prerelease。
- [ ] 哈希与下载资产一致。

## 11. 文档与 Agent 手册

- [ ] README 只描述真实已实现能力。
- [ ] 架构变化同步 `docs/ARCHITECTURE.md`。
- [ ] 接口变化同步 `docs/CORE_API.md`。
- [ ] 模块变化同步 `MODULES.md` 和模块 README。
- [ ] 环境/命令变化同步 `docs/DEVELOPMENT.md`。
- [ ] 发布变化同步 `docs/RELEASING.md`。
- [ ] Agent 任务路由或关键不变量变化同步 `.agent/`。

## 12. 评审输出建议

每个问题应包含：

- 具体文件和最小行范围；
- 可触发场景；
- 用户或系统影响；
- 为什么现有保护不足；
- 可行的修复方向；
- 优先级。

没有可操作问题时明确说“未发现阻塞问题”，并列出实际检查范围和仍未验证的部分。不要把纯风格意见伪装成高优先级缺陷。
