# 周期作业模块

内置模块 `builtin.assignment.recurring` 提供 `assignment.schedule` 能力。规则与节点保存在模块私有表中，生成结果仍是核心 `assignments` 作业。

支持：

- 每 N 天、每 N 周的指定星期、每 N 月某日或第 N 个星期几；
- 前项进入“待提交”或“已提交”后生成下一项的序列；
- 基于学期第 1 教学周周一的教学周计划；
- 去重排序的自定义日期清单；
- 次数/结束日期双重结束条件、独立截止规则和周期共享文件。

调度在应用读取快照、恢复周期和关联作业状态变化时幂等执行，不启动常驻后台进程。一次待补齐不超过 10 项时自动生成；超过 10 项时保留为审核清单。

关闭模块只停止调度并隐藏周期界面，已生成作业会恢复为普通作业行。彻底删除周期定义也不会删除已生成作业或磁盘文件。

## 模块边界

- `backend.rs` 持有 schema、规则校验、物化、调度、生命周期钩子和模块管理分派；
- `frontend/` 持有周期列表扩展、时间线、创建/编辑抽屉、设置卡、桌面调用和浏览器预览；
- `modules/registry.rs` 负责把模块后端加入编译期清单；主程序只提供通用 `AppModule`、作业列表扩展点、文件关联服务和 `manage_builtin_module` 转发，不包含周期作业 ID、操作名或成功文案；
- 实际作业保存和共享文件关联仍由核心接口执行，以维持事务、路径校验和审计历史。

桌面模块服务通过单一命令发送 `{ moduleId, operation, payload }`，宿主检查模块是否存在且已启用后，将请求交给本模块的 `manage` 函数。新增周期模块操作不需要修改 `src-tauri/src/lib.rs` 的命令列表。
